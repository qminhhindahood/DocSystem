# 08 — Make conversion feedback accessible

**What to build:** Make lifecycle changes perceivable to assistive technology and ensure the primary conversion actions are comfortable touch targets on supported layouts.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] Queued, processing, warning, completed, and failed changes are announced through an appropriate live status region without duplicative announcements.
- [ ] Download and report controls meet the documented minimum 44 by 44 pixel touch target on touch layouts.
- [ ] Keyboard focus, visible labels, and existing status text remain intact, with automated accessibility-oriented component coverage.
